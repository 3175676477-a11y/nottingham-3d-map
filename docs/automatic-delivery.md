# 自动放入文稿/codex

目标：用户在 GitHub 创建仓库，Codex 完成网页任务并发布后，Mac 的登录后台服务每 5 分钟扫描账号 `3175676477-a11y`，自动生成 `~/Documents/codex/<仓库>/最新版本.webloc` 和 `历史版本.webloc`。文件夹直接在文稿创建，不经过下载目录。既有 `codex` 目录直接沿用，只更新本工具管理的两个链接，不删除其他项目。

## 一次性升级 Mac

运行 `scripts/install-local.mjs` 安装升级。依赖 Mac 上的 Node.js 和 Git，不需要 npm 安装；安装会复制纯 Node 运行文件到 Application Support，替换原 LaunchAgent 的运行入口，保留 43173 端口、原桌面链接、原缓存及历史版本。安装文件无需保留，退出终端不影响后台服务。Mac 登录时启动，睡眠/关机或离线期间不能检查新发布内容，恢复后继续同步。

网页顶部“自动归档”提供一段一次性安装命令和服务状态；云端不能代替用户在 Mac 授予本地目录访问并安装登录服务。Linux 自动测试不能证明 macOS launchd/TCC 已通过实机验证。

## 新仓库交付约定（给 Codex）

自动发现的是**已发布的静态网页**，不执行陌生仓库中的 npm 脚本，不把任意源码仓库当作网站。需要后端、数据库、登录服务的项目应单独部署后端，不能宣称静态构建已经支持这些服务。

适用于使用此配置的每个新网页仓库：

1. 在用户选定的仓库完成修改，运行适用测试和生产构建；资源及页间链接使用相对路径。
2. 提交源码并推送该仓库的工作分支，不能只把成果留在云端工作区。
3. 将可独立打开的构建目录发布到**同一仓库**的 `codex-releases` 分支，使用不可变 `releases/v-<源码提交前12位>/`。
4. 维护根目录 `manifest.json`：`schema:1`、`latest`、`entry`（例如 `index.html`）和 `versions:[{id,sourceCommit,date,label,entry}]`。
5. 每次新增一份构建；旧目录不得覆盖、删除或强推。只有 manifest 指向的 HTML 入口存在，Mac 才创建快捷方式。
6. 可使用本仓库提供的纯 Node 发布工具：`node /path/to/publish-task.mjs --repo /workspace/<仓库> --dist dist --entry index.html`。构建与测试由当前任务完成，此工具只发布已经验证、已提交源码对应的产物。
7. 遇到同步发布冲突，重新基于远端历史发布，不能 force push。

工具源：`scripts/publish-task.mjs`，独立文件，无第三方依赖。

当前 `nottingham-3d-map` 继续沿用 `solar-atlas-releases` 和 `npm run release`，已有历史不迁移、不删除。其他仓库不复用本项目的历史数据，独立路由为 `/projects/3175676477-a11y/<仓库>/`。

**作用域**：这个约定必须随 Codex 任务的启动说明/自定义指令生效。仅安装 Mac 程序不能让未获知约定的其他 Codex 环境自动发布任意新仓库。当前环境的启动说明可保存该规则；使用其他环境时也要配置同样的交付规则。

## 仓库发现与状态

默认通过 GitHub 公开仓库 API 分页发现，不需要公开仓库 Token。本机有已登录的 `gh` 时，可用现有授权发现自己拥有的私有仓库；克隆还需本机 Git 的读取权限，不保存或显示令牌。扫描失败、仓库不可访问、构建缺失、目录无写权限时，状态页显示错误，已缓存任务继续保留。`http://127.0.0.1:43173/tasks.html` 查看最近同步时间、已发布任务和待发布仓库。

服务只绑定本机回环地址，拒绝非读取请求。仓库名称和入口路径经过验证；文件服务检查 realpath，禁止仓库内的符号链接读取发布缓存外的文件。文件夹入口不指向具体版本 ID，因此发布新版后无需替换入口。
