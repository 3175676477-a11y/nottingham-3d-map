Codex 完成，文稿里自动出现

你创建 GitHub 仓库并交给 Codex。网页任务按统一格式发布后，Mac 每 5 分钟检查你的公开仓库，自动放入：

文稿/codex/
├── nottingham-3d-map/
│   ├── 最新版本.webloc
│   └── 历史版本.webloc
└── 新仓库名称/
    ├── 最新版本.webloc
    └── 历史版本.webloc
正在检查本机同步器…

一次性安装或升级

点击复制，把这段代码在 Mac 终端运行一次。它直接安装到本机并创建文稿目录，不使用“下载”文件夹。以后不必为每个仓库重装。

文稿里已有的 codex 文件夹会直接沿用，工具只更新每个仓库内的两个网页入口。你已有的其他项目文件不会被清空。
让新仓库自动交付
后台识别各仓库的 codex-releases 发布分支。Codex 需要在完成构建和验证后发布该分支。空仓库或只有源代码的仓库会等待发布，不会产生打不开的快捷方式。
此云环境会提供统一交付规则；若换用另一个 Codex 环境，请把下面这句话加入该环境的自定义指令一次：
网页任务完成后，运行测试和生产构建、提交并推送源码；将静态网页发布到同仓库 codex-releases 分支的不可变 releases/v-<提交前12位>/ 目录，维护根 manifest.json（schema:1, latest, entry, versions 含 id/sourceCommit/date/label/entry）。资源路径使用相对路径，保留全部历史版本。我的 Mac 同步器会自动在 文稿/codex/仓库名 下生成最新和历史入口。不要只把成果留在云端工作区。
仅安装 Mac 同步器不会替其他 Codex 环境自动设置发布规则；需要后端的项目还需部署相应服务。
